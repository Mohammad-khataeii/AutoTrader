# V4.2 shadow laboratory architecture

Shadow experiments reuse `PersistentTradingRepository`, the execution gateway, side-aware IOC pricing, posting engine, immutable journal, risk limits, reservations, position manager, partial targets and crash recovery. Each experiment receives EUR 500 once in its own PostgreSQL database inside the existing AutoTrader PostgreSQL service. The official `paper-eur` database retains its own account, balances, orders, fills, reservations, risk periods, cooldowns and journal.

This boundary is deliberate: the original balance key and several queries assume one financial account per database. Merely changing `account_id` would mix balances and risk. Physical database separation preserves the tested financial engine. This is bounded to four retained experiments, including stopped ones; no automatic deletion or refunding exists. Database connections use the existing service credentials; this is an application isolation boundary, not hostile PostgreSQL-superuser multitenancy.

Runtime: worker scanner → shared validated observations → `ShadowRuntime.scan` → frozen original/experimental engine → `DecisionEngine` → existing allocation → `ShadowExecutionGateway` → `ShadowTradingRepository` admission → existing broker/journal. The independent protective loop monitors official positions and all shadow experiments, including paused/stopped ones, using one validated book per symbol per cycle. No extra HTTP acquisition occurs per experimental strategy. Shadow evaluation makes no AI calls; existing official quotas remain unchanged.

The official database stores a durable experiment registry. Provisioning records CREATING before allocating a server-generated database name, applies Alembic, writes an immutable domain identity, initializes funding idempotently and reconciles before SHADOW_ACTIVE. A repeated request resumes the same domain. Unknown request/account/strategy identities cannot choose a database URL or spend official reservations. D2 is not an entry preset. Registry configuration and domain markers are immutable in PostgreSQL; state changes preserve frozen source, parameters, costs and data kind.

Each shadow repository checks the actual database name, immutable manifest hash and exclusive account identity before financial locking. Its account identity is read-only. The shadow gateway rejects official repositories. An ordinary repository refuses to initialize an official account inside a marked shadow database. Entry admission checks exact strategy/version/parameters/costs, qualified signal and current source fingerprint. Source changes suspend entries while existing protection continues. The official research gate is never disabled for shadow use, including process acceptance with ENVIRONMENT=test.

API: authenticated GET/POST `/api/shadow`, GET detail/export, full authenticated NDJSON history exports for journal/orders/fills/equity, and POST pause/resume/stop. DTOs forbid extra fields. There is no unrestricted account-ID or force-trade input. Financial history in the dashboard is a recent 500-record window; headline fees and maximum drawdown use full stored history. Stopped experiments cannot be resumed or reset through the lab.

All test-environment experiments are labeled SYNTHETIC_ACCEPTANCE even when the API process has no replay-file setting. Live experiments require genuine Revolut X observation provenance. Historical diagnostics are separately labeled HISTORICAL_OHLCV_PROXY. A shadow status never grants PAPER_APPROVED.

Restore boundary: a registry restored under a different official database name must not follow pointers into the original shadow databases. The lab rejects that context. Restoring all domains with their original names into a separate isolated PostgreSQL cluster preserves their identities; same-cluster remapping needs an explicit reviewed recovery procedure. Never run a restored worker against unreviewed database mappings. Archives and all newer financial history must be retained.

After explicit approval of the final Git release, the intended initial production set is one original compression configuration and one B2 configuration, frozen independently. No production experiment was activated before the local-first instruction stopped further operations. Thirty prospective days begin only after actual activation. No completed 30-day result is claimed by implementation or deterministic acceptance.

The full isolated-cluster restore was executed with a real admitted A2 BUY and a subsequent partial target only on the restored domain; see V4_2_SHADOW_FINANCIAL_INTEGRITY.md. Per-experiment errors are contained so another healthy domain retains protective monitoring.
