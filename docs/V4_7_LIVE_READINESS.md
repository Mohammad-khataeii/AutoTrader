# V4.7 future live boundary

Live readiness: **NOT READY FOR A REAL-MONEY PILOT**. This release authorizes only virtual EUR accounting. `Settings` rejects live mode, Compose sets `LIVE_TRADING_ENABLED=false`, and `RevolutXPublicClient` accepts only public GET paths. There is no reachable authenticated order transport or automatic paper-to-live promotion.

The reusable broker boundary is `PaperExecutionGateway.execute_entry_decision` / `execute_exit`. It separates market observations, account admission, idempotent intention, order transitions, fills, journal posting, reconciliation and protection. A future exchange adapter must implement those responsibilities without using the simulated-fill dispatcher. A real account must have a distinct ledger, explicit real-money budget and independent authorization.

The [official Revolut X API reference](https://developer.revolut.com/docs/api/revolut-x-crypto-exchange), inspected October 26, 2026, distinguishes public `/2.0/public/order-book/{symbol}` from authenticated `/1.0/order-book/{symbol}`. Public pair configuration, tickers and candles use `/1.0/public/…`. Versions must be chosen per endpoint. Authenticated requests require Ed25519 signatures over timestamp, method, path, query and body. None of these credentials or signatures is needed for the implemented paper broker.

Future implementation must verify the then-current contract for `POST /1.0/orders`, `GET /1.0/orders/active`, historical orders/fills and `GET /1.0/balances`. The actual order request uses `client_order_id`, `symbol`, `side` and `order_configuration`; generic exchange payloads are not interchangeable. Test signatures, permission rejection, duplicate-client-ID behavior, uncertain acknowledgement, network reconnection, partial fills, actual fees, balance synchronization and restart recovery with mocked transport before any separately approved connectivity test. Exchange-side protection and API/account restrictions remain unverified.

A live-readiness decision must also review independent prospective sample size, net expectancy, adverse regimes, drawdown, paper-versus-live depth/queue assumptions, external reconciliation, emergency shutdown and recovery. Neither a synthetic lifecycle nor this reused historical panel meets those conditions. No exchange keys were requested, opened or created; no authenticated mutation, funds transfer or live activation was performed.
