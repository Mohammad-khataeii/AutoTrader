## Failure and rollback

Stop on any failed backup, migration, reconciliation, profile, source/image, protection or access check. Preserve failed-release and restore diagnostics, financial/source backups, the old Compose wrapper and rollback images. Do not retry the old V4.9.1 activation process against a new healthy account.

The helper can recover the previous images only while all ledgers are known flat. It never restores an older financial snapshot automatically. Entries remain paused, with monitoring retained; unknown/open exposure prevents automatic image rollback. Corrections originate locally, pass tests/builds, receive a new commit and immutable artifacts, and need separate exact-release approval.

Because a newer frozen profile may be incompatible with old entry code, rollback is **monitoring-only** until a separately reviewed compatible entry transition. Do not resume old code against changed primary authority. Restoring source/images is distinct from restoring financial state; newer transactions must always be preserved.

After successful verification, remove only uniquely owned temporary transfer/verification artifacts. Retain financial/source backups, required rollback images, named database volumes, model/dataset history, release evidence and all unrelated applications.
